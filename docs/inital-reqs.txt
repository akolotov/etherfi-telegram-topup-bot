Задача: бот, который при уменьшении баланса onchain аккаунта ниже определенного уровня, создает транзакцию в Safe Wallet для пополнения этого аккаунта.

Бот
- Знает набор Telegram акаунтов, которые могут с ним взаимодействовать
- Для каждого из Telegram акаунта 
    - Знает аккаунт на Optimism сети (target account)
    - Знает пороговое значение баланса target account, при опускании баланса ниже которого нужно начать процедуру пополнения баланса (target account balance threshold)
    - Знает желаемое значение баланса target account, до которого нужно пополнять аккаунт (target account max balance)
    - Знает периодичность, с какой проверять баланс акаунта (target account balance check interval)
    - Знает адрес Safe Wallet в сети Arbitrum (safe account)
    - Имеет приватный ключ (хранится в keychain) одного из подписантов Safe Wallet (safe owner private key)
    - Знает максимальное количество повторных нотификаций, которое может послать пользователю с сообщение о низком балансе (low balance notification limit)
    - Знает временной промежуток, через который нужно послать напоминание пользователю о пополнении баланса target account (low balance notification cooldown interval)
- Знает админ аккаунт - аккаунт, которому отправляются сообщения об ошибках. Админ аккаунт может быть, а может и не быть одним из акаунтов, с какими ассоциирован target account.
Данная настройка в JSON файле

Бот для каждого пользователя
- Раз в <balance check interval> узнает баланс target account
- Если баланс ниже balance threshold, то бот отправляет на Telegram account, который ассоциирован с этим target account, сообщение о низком балансе с inline кнопками “top up” и ignore
- Если через очередные <balance check interval> после сообщения о низком балансе, баланс все еще низкий, то бот удаляет кнопки в своем предыдущем сообщении и отправляет новое сообщение о низком балансе снова с кнопками “top up” и ignore. Так происходит low balance notification limit раз, начиная с самого первого сообщения о низком балансе. После последней нотификации, новые нотификации не появляются, если баланс все еще низкий, в течение low balance notification cooldown interval, хотя проверка баланса все также происходит раз в <balance check interval>. Если в любое время баланс target account становится выше target account balance threshold, то счетчик повторов или флаг того, что был заведен таймер для сбрасываются
- Если пользователь нажимает ignore, бот удаляет кнопки в своем сообщении и продолжает работать, как ранее. Счетчик повторов нотификаций об low balance или флаг того, что был заведен таймер для сбрасываются
- Если пользователь нажимает top up, то бот удаляет кнопки в своем сообщении,  сбрасываются счетчик повторов или флаг того, что был заведен таймер, создает в Safe Wallet транзакцию на пополнение target account до значения равного по тому же адресу, ч, но в сети Arbitrum, затем отправляет пользователю нотификационное сообщение, что транзакция создана в Safe Wallet, что пользователю нужно добавить подпись и сделать execute.
- Если через <balance check interval> бот видит, что в Safe Wallet транзакция до сих пор не исполнена, то он не отправляет сообщение пользователю о том, что баланс низкий, еще раз. Это происходит до тех пор, пока не проходит low balance notification cooldown interval с момента отправки нотификации о создании транзакции. После low balance notification cooldown interval, отправляется сообщение о том, что существует pending транзакция.
- Если транзакция исполняется/отменяется, то бот возвращается в обычное состояние проверки баланса через balance check interval
- Если баланс увеличился так, что стал больше target account balance threshold, то бот воспринимает это событие ровно также, как если бы транзакция была исполнена.
- Если пользователь заблокировал бота (да, такое событие может быть отловлено ботом - проверено), то сообщения пользователю перестают отправляться, проверка баланса перестает осуществляться, все заведенные таймеры или счетчики сбрасываются - для бота все должно после этого выглядеть, как если бы пользователь еще ни разу не нажимал start.
- При попытке отправить сообщение, может получить 403 от телеграмм сервера, это расценивается, как если бы пользователь в этот момент послал блокировку.
- Проверка баланса через balance check interval не стартует пака пользователь не сделал start для бота. Для тех пользователей, которые уже с ботом взаимодействовали и потом заблокировали, визуально действие будет “restart”, но для бота оно означает тоже самое, что и start — бот не должен воспринимать пользователя, как кого-то с кем он уже когда-то взаимодействовал.
- Сохраняет состояние так, чтобы после перегрузки бота он мог бы продолжить с того же момента, который был до перезагрузки.

Если Telegram пользователя нет в конфигурационном JSON, то на действие start (restart для тех пользователей, которые уже с ботом взаимодействовали и потом заблокировали)  ничего не происходит, все сообщения от такого пользователя игнорируются.

Единственное ожидаемое ботом действие от пользователя в чате - нажать на кнопку Top Up или Ignore. Если пользователь отправляет боту сообщение (причем даже сообщение start), то оно игнорируется. Если пользователь делает reply или выставляет реакции на сообщения - эти действия игнорируются. Возможно, такое игнорирование можно достичь через явное указание ботом при запуске, какие события он хочет получать от телеграм сервера.

Нажатие на старые кнопки (бот не в состоянии ожидания нажатия кнопок или кнопка нажата не в самом последнем сообщении, что отправил бот) игнорируются. 

Проверка баланса или создание Safe Wallet транзакции или проверка ее статуса можно считать для простоты синхронными действиями. При создании Safe Wallet транзакции баланс может получаться еще раз, чтобы в транзакции указать нужное количетство токенов для пересылки. Поэтому последний полученный баланс хранить ботом только для нужд создания Safe Wallet транзакции - не нужно.

Если бот не может получить баланс - он посылает сообщение админу, и продолжает быть в режиме замера баланса каждые <balance check interval>

Если бот не может сгенерирвать/зарегистрировать транзакцию в Safe Wallet, то посылает сообщение админу и, затем, снова переходит в режим замера баланса каждые <balance check interval>

Для простоты мы считаем, что все сообщения до телеграм сервера могут быть отправлены успешно (кроме варианта c 403).

Механика такова, что да, действительно нужно транзакция для Safe Wallet создается в Arbitrum. Как баланс пополняется в Optimism - за пределами функциональности бота. Для простоты считаем, что после исполнения транзакции в Arbitrum, баланс в Optimism пополняется мгновенно (по крайней мере так будет казаться боту, если balance check interval подобран так, чтобы баланс успел пополнится между двумя тиками.

balance check interval - это тик бота как для проверки баланса, так и проверки исполнения транзакции Safe Wallet (но на самом деле боту не важно исполнилась она или нет - важно, что баланс в итоге увеличился). Если так будет проще, то low balance notification cooldown interval может быть разбит на несколько balance check interval, то есть бот будет проверять не истек ли ow balance notification cooldown interval  в очередной раз после истечения balance check interval
